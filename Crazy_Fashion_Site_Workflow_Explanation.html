3. Technical State Engine & Data Pipeline

SECTION 03

The website operates on a centralized reactive state model defined in script.js. Every user interaction modifies the state object, which triggers targeted UI render cycles and persists changes to browser storage:

3.1 Central State Data Schema

const state = {
  cart: JSON.parse(localStorage.getItem("crazy_cart") || "[]"),         // [{ productId: 1, size: "M", qty: 2 }]
  wishlist: JSON.parse(localStorage.getItem("crazy_wishlist") || "[]"), // Product IDs: [1, 7, 10]
  selectedCategory: "all",     // 'all' | 'shirts' | 'jeans' | 'tshirts'
  searchQuery: "",             // Real-time typed keyword
  sortBy: "featured",          // 'featured' | 'price-asc' | 'price-desc' | 'rating'
  activeCoupon: null,          // null | { code: 'CRAZY50', discount: 0.50 }
  coupons: {
    CRAZY50: 0.50,             // 50% discount
    WELCOME10: 0.10,           // 10% discount
    FREESHIP: "free_shipping"  // Delivery fee waiver
  },
  selectedSizes: {}            // Map of productId -> chosen size string
};

3.2 LocalStorage Persistence Keys

Storage Key Data Type Lifecycle & Persistence Behavior
crazy_cart JSON Array Persists customer shopping cart items across page refreshes, tab closures, and multi-page routing (index.html ↔ categories.html ↔ Nextpage.html).
crazy_wishlist JSON Array Stores product IDs flagged as favorites by the user. Synced across all active browser tabs via the window storage listener.
crazy_drop_target_time Unix Timestamp Dynamic rolling launch date for the capsule drop countdown clock (maintains exactly 4 days, 18 hours from initial site entry).
crazy_drop_waitlist JSON Array Logs customer VIP waitlist entries (Name, Email, Target Drop Garment, Timestamp) directly into client storage.

3.3 Cross-Tab State Synchronization

If a customer opens the store in multiple browser tabs simultaneously (for example, browsing shirts on tab 1 while inspecting denims on tab 2), state remains unified in real-time through the window storage event listener: 

window.addEventListener("storage", (e) => {
  if (e.key === "crazy_cart") {
    state.cart = JSON.parse(e.newValue || "[]");
    updateBadges(); renderCartDrawer();
  } else if (e.key === "crazy_wishlist") {
    state.wishlist = JSON.parse(e.newValue || "[]");
    updateBadges(); renderProducts();
  }
});

Performance Advantage

By isolating data mutations inside pure JavaScript functions and storing serializable state in LocalStorage, page transitions are instantaneous without requiring backend session re-validation.

4.2 Price Calculation & Free Shipping Formula

Every time the cart contents change, getCartCalculations() evaluates the financials: 

function getCartCalculations() {
  let subtotal = state.cart.reduce((sum, item) => {
    const product = PRODUCTS.find(p => p.id === item.productId);
    return sum + (product ? product.price * item.qty : 0);
  }, 0);

  let discount = 0;
  if (state.activeCoupon && typeof state.activeCoupon.discount === "number") {
    discount = Math.round(subtotal * state.activeCoupon.discount);
  }

  // Orders > ₹999 get free delivery; else ₹99 fee
  const shipping = (subtotal > 999 || state.activeCoupon?.code === "FREESHIP" || subtotal === 0) ? 0 : 99;
  const grandTotal = Math.max(0, subtotal - discount + shipping);

  return { subtotal, discount, shipping, grandTotal };
}

5. Checkout Simulation & VIP Drop Engine

SECTION 05

5.1 Multi-Payment Simulated Transaction Flow

The checkout gateway in index.html and categories.html simulates an enterprise payment gateway experience with three distinct payment rails:

A

Credit / Debit Card Rail

Provides input fields for 16-digit Card Number, MM/YY Expiry, and CVV with masked formatters. Pre-filled with a testing sandbox credential for instant user evaluation.

B

UPI / QR Code Rail

Accepts Virtual Payment Addresses (VPA) and displays a simulated Dynamic QR Code for scanning via GPay, PhonePe, or Paytm with instant verification badges.

C

Cash on Delivery (COD) Rail

Enables instant one-click door delivery verification without electronic payment requirements.
